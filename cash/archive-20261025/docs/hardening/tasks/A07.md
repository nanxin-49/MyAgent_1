## A07/N10（P1）——API 内置 Eval 不能变更聊天业务数据

**依据**：`EVAL_SHARED_STATE`；`api/main.py:207/727`、`evaluation/evaluator.py:321`。startup evaluator 与 `/chat` runtime 共享状态；审查隔离复现显示调用 evaluator 后，原业务订单变 `cancelled`。**CLI 使用隔离 fixture 不等于 API `/eval/run` 已隔离。**

**先写测试**：同一个应用，调用 `/eval/run` 运行包含危险动作的 demo case 前后，读取正常 `/chat` 对应的业务数据快照；正式数据**必须保持不变**。还要确保 Eval 的行动模拟结果只在实验命名空间/副本中。配合 A03/N02-ops 限制无权限触发。

**最小修复**：让 API evaluator 获取隔离的 Provider + ActionStore + Runtime，或在没有安全隔离条件时明确禁止会产生副作用的内置 Eval。不能只依靠 UI 不展示按钮；不得破坏已有 CLI 评测的有效隔离模式。

**DoD**：不经授权不可触发 Eval；即使授权运行也不污染 `/chat` 数据；检查 CI 回归和 fixture 差异。若新 Eval baseline 会覆盖上一轮不同数据集的基线，同时记录版本校验待办，**不覆盖历史冻结报告**。
