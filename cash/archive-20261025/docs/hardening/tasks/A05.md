# A05｜先修知识/RAG 契约，再做 RAG 质量对照

> **三个独立小轮次**：`A05/N06`、`A05/N07`、`A05/EXPERIMENT`。**不得一次执行三个**。审查报告 N06/N07 已有隔离观察；修复前不能把旧文档引用/空重排判为“有用检索”的输出拿来宣称质量提升。

## A05/N06（P1）——Knowledge 更新与旧片段退役

**依据**：N06 / `KNOWLEDGE_UPDATE`；`mcp/knowledge_base.py:87/134`、`mcp/rag_contract.py`。审查观察：同一 `document_id/version` 把 7 天改 30 天后，两个 chunk 仍在、citation 相同；发布 v2 后旧 v1 仍可 `usable`。

**先写测试**：同 doc/version 重写内容 → 旧 chunk 不可作为 usable；文档版本升级 → 旧政策不能与当前政策同时作为 active；`effective_at` 对未来版本的限制仍在；查询不能因 citation 去重只保留过时 chunk。可为政策权威规则另保留 PolicyEngine 一致性待办，不能靠 RAG 文案绕过 Policy。

**最小修复**：基于已用的 Chroma collections/metadata 引入明确的文档有效/退役机制和原子性可接受的替换过程；只动 Knowledge CRUD 与版本过滤，不重建整个知识平台。

**DoD**：更新前后同一查询结果真实反映现行内容；旧引用不可用；有明确的版本/失效语义及回归。

## A05/N07（P1）——Rerank 空结果伪 usable

**依据**：N07 / `RERANK_EMPTY_USABLE`；`mcp/tool_manager.py:431/439`。审查观察：模型返回**合法 JSON `[]`**，最终 success=true、retrieval_status=usable，却没有证据/引用；非法 JSON 的 fallback 不能覆盖这类输入。

**先写测试**：空数组、部分非法 doc id、重复 id、非 JSON、re-rank 不可用、正常有效数组；明确各 case 的 `retrieval_status`、hits、citation、`reranked` 的一致性。

**修复规则**：无可用证据不得标 `usable`；若选择 fallback 到初检，必须确实存在有效初检证据，且不谎称 rerank 成功；否则明确 `no_evidence`/`unavailable` 等现有契约支持的状态。不让模型自由输出任意引用 id。

**DoD**：状态、hits、citation、重排标识一致；原有 RAG 测试通过。

## A05/EXPERIMENT（高价值，N06/N07 后进行）

**范围**：先冻结 **≥30 条**中文 query 与 gold evidence，覆盖同义、歧义、无答案、过期/被替换政策、混合商品和真实业务范围；保存冻结语料、chunk、embedding 版本、Top-K。

- `B0`：现有 `char-bigram-1024-v1` lexical baseline（**不是预训练语义 Embedding**）。
- `B1`：指定语义 Embedding，同一 corpus/gold（需模型资源/下载/费用授权；未具备条件标 partial）。
- `B2`：B1 + rerank（有预算才做）；`B3`：query rewrite 组合仅可选。
- 指标：Recall@1/3/5、MRR（只计有 gold evidence 题）、无答案误报率、citation/evidence precision、P50/P95 latency、模型调用和 token/费用。**检索找到证据 ≠ 生成答案每句话正确**。
- 新数据放 `evaluation/reports/hardening/A05/<run-id>/`，包含逐题输出、聚合、错误样例、环境/commit；不可覆盖 T09–T12 历史。
- 不默认替换 Demo 生产检索策略。若 B1 质量、成本或延迟收益不明确，可以基于实验继续保留 B0。

**DoD**：`B0+B1` 可重复且对比口径明确才能叫 `experiment_complete`；仅完成 B0 必须标 `partial` 并说明原因。实验完成后写 `docs/engineering/A05-rag-evaluation.md`，可以清楚讲出失败案例及取舍。
