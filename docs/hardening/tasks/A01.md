# A01｜Agent Loop 及请求级恢复（条件任务，P1）

> 从 V2 的“第一项主任务”调整为 **P0 + 结果一致性处理后的条件任务**。审查确认 C03 复合任务缺乏逐项完成状态，但**不能据 C03 就宣称最后一轮只读 `tool_use` 已隔离复现**。分问题处理。

## A01/C03——最后一轮工具调用与复合请求完成状态

**证据**：报告 C03；`agents/agent_orchestrator.py:261/287/410`；当前最多 3 次主 Agent 模型调用，同轮多个工具由后端串行调用，末轮 Action 回执只取最近一个动作，不能证明全部子诉求完成。

**先测**：
1. Fake SDK 最后一轮仍为只读 `tool_use`，记录工具执行、模型调用、用户最终文本与 Trace，确认是否实际出现未收尾错误。
2. “查物流并申请退款”这样的两事项请求，一项成功一项失败/未调用时，不能把单一成功 Action 回执表达成“全单完成”。
3. 多 `tool_use` 同轮串行，明确哪些可以同轮独立、哪些依赖上轮结果；**不默认改成全局并行**。
4. 工具/模型调用有明确总次数上限；危险动作不能因末轮/异常自动再次执行。

**若复现**：采用最小完成状态或确定性降级；区分 `partial_completed`、`needs_input`、`failed` 与 `completed`，不新增大规模任务规划器。若末轮缺陷未复现，仅保存测试并写 `verified_no_fix`；不虚构修复故事。

## A01/N11 / C07（可选）——读工具超时与请求预算

**证据**：N11 隔离复现同步工具 timeout 后 worker 仍继续，启用读重试时会重叠；C07 无统一总请求预算，Demo 缺中断和进度。**未发现危险动作被读重试机制自动重试。**

只针对**读工具**测试：超时后原 worker 的状态、连续重试是否重叠、并发许可和限流；记录“超时不能强杀后台线程”的机制。若时间不足将 N11/C07 记录为 known_open；不顺手建设流式 UI 或异步任务平台。

**学习笔记**：只有 A01/C03 进行了真实复现和针对性变更时完成 `docs/engineering/A01-agent-loop.md`；如仅验证边界，短记录即可。个人练习：不用 Codex 实现最小有界 `tool_use → tool_result` Loop。
