## 调用路径变化

- 失败工具结果现在统一带 `error_code`、`error_type`、`retryable`、`suggested_action`；业务 Provider 的嵌套 `error` 与动作 `action_result` 原字段保留。
- `BaseAgent` 在写入 `tool_result` 前调用 `truncate_tool_payload(payload, max_tool_result_chars)`；Trace 仍从完整 payload 提取字段，并记录 `truncated`。
- `error_feedback=False` 时，截断后再覆盖为 `{"success": true, "acknowledged": true}`，消融语义不变。
- `suggested_action` 只是给模型的下一步建议，不改变 Policy、权限或执行结果。

## 新发现的问题与限制

- `suggested_action` 是建议，真实模型可能忽略；H3-2 不声称恢复率提升，只提供可对比的信息通道。
- 截断对模型可见 payload 生效，生产默认 8000 字符；本仓库实测最大 `retrieval_hits` 约 956 字符，正常请求不受影响。若非字典 payload 超限，会变成带 `preview` 的对象。
- 业务 Provider / RAG / 动作拒绝的失败 payload 增加顶层字段，是**失败路径的协议扩展**；成功路径未变。
- 重复调用的参数规范化仍未做（H3-1 遗留），不在本任务范围。
- 写动作超时策略未变（H3-1 结论，N11 归 H4-3）。
