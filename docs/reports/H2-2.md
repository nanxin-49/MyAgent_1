## 录制证据说明

- `TrajectoryRecorder` 是客户端包装器，生产不安装；unit 测试用 Fake SDK 验证 response content/stop_reason/usage 与 request hash 捕获。
- `h1_1_s1b.json` 由 H1-1 repair1 的真实 `model_ledger.json` 转换，`evidence_level=converted_h1_1_ledger`；只保留 support 轮，RAG rewrite 事件省略；缺少 request messages/system/tools，已置 null 并在 provenance 标注。**不是本次新模型调用**。

## 限制

- `invalid_arguments` 在 handler 级注入得到 `error_type=tool`，不是 validation 原形（`attempts=0`）；真实 validation 需脚本化模型传坏参数。
- RAG 失败在 agent 边界统一为 `degraded`；区别码在适配层注入。
- 动作工具无 timeout 分支；动作故障用 backend `fail_operations`。
- 重试会消耗调用次数；可见失败需 `sticky` 或 `on_call >= retry`。
- 每条 case 使用独立隔离运行时；不做真实模型 / live Redis-Chroma 的新运行。
