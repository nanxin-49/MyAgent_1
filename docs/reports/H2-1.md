# H2-1 — 评测框架：组件开关 + 脚本化假模型

- **日期**：2026-10-25
- **分支**：`claude/cartcare-harness`
- **状态**：`verify`
- **证据层级**：unit / Fake SDK（无真实模型、无 live Redis/Chroma）

## 目标

让 harness 的五个组件可以独立关闭，并提供一个按 JSON 脚本输出多轮工具调用和最终文本的假模型。默认全开；关闭只在评测运行时允许，线上 `/chat` 不暴露开关。

## 改动

| 文件 | 内容 |
| --- | --- |
| `core/harness.py` | 新增 `HarnessConfig`：五个开关、`max_tool_rounds=3`、`unguarded_max_tool_rounds=1000`、`mode=production/evaluation`；非 evaluation 关闭任一开关 raise |

| `memory/conversation_memory.py` | `MemoryManager` 接收 `harness`；`context_compression=False` 时不触发 15 条压缩 |

## 开关行为

| 开关 | 开启（默认） | 关闭（仅 evaluation） |
| --- | --- | --- |
| `policy_guard` | PolicyEngine 正常 allow/deny/require_approval | `_evaluate` 返回 `harness_policy_disabled` 的 ALLOW；只配假后端 |
| `error_feedback` | 失败工具的错误详情回传模型 | 中性 `{"success": true, "acknowledged": true}`，仍保留每个 tool_use 的 tool_result |
| `context_compression` | 15 条触发摘要 + 最近 5 条 | 不压缩；原始轮次保留 |
| `loop_control` | 最多 3 轮工具循环 | 上限 1000（有限硬停止）；4 轮脚本可完成 |
| `output_consistency` | 交接/动作回执与“已完成”声明保护 | 返回模型原文；建单/幂等/`allowed_reason` 不变 |

关键断言：

- 生产模式 `HarnessConfig(policy_guard=False)` / `loop_control=False` 均 raise；`HarnessConfig.evaluation(...)` 可用。
- `ChatRequest` 与 `EvalRunInput` 无 `harness` 字段；生产 `SupportRuntime` 默认 `HarnessConfig()` 全开。
- `policy_guard=False`：过期订单从 `refund_window_expired` 拒绝变为完成，后端执行 1 次。
- `error_feedback=False`：第二次模型调用的 tool_result 不含 `not_found/error`。
- `context_compression=False`：16 条消息保留、无摘要；默认压缩且摘要存在。
- `loop_control=False`：4 轮工具完整执行并返回最终文本；默认第 3 轮后失败。
- `output_consistency=False`：模型声称“已成功创建交接”时原文返回；默认替换为“本次未创建人工交接记录”。

## 限制

- `context_compression`：当前 `EvaluationRuntimeFactory` 不构造 `MemoryManager`，因此该开关在隔离评测运行时暂无可观察效果；本任务在 MemoryManager 单元层实现并验证。H2-2 若接入回放/记忆再补工厂级用例。
- `policy_guard=False` 只允许 `HarnessConfig.evaluation`；生产构造会 raise。H2-4 的“模型 + 工具”基线仍应保留 PolicyEngine。
- `loop_control=False` 仍有 1000 轮硬停止。
- 本任务不做录制回放、故障注入、轨迹打分、pass^k（H2-2）。
