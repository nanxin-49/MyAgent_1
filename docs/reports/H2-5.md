## 方法与口径

- **数据**：冻结 `a05-corpus-v1`、`a05-dataset-v2`（30 题：21 有答案 / 9 无答案）、`a05-threshold-dev-v2`（16 题：8/8）；B0 历史结果只读保留。
- **模型**：`BAAI/bge-small-zh-v1.5`，revision `7999e1d3359715c523056ef9478215996d62a620`；`model.safetensors` 95,827,648 bytes，SHA256 `354763b9...` 已本地校验；512 维、CLS pooling、L2 normalize。
- **输入**：document = `title + "\n" + content`；query = `为这个句子生成表示以用于检索相关文章：` + query；所有输入 ≤512 tokens，未截断。
- **组别**：
  - `b0`：现有 char-bigram-1024；使用已锁定的 dev 阈值 **0.20**（`b0_lexical_calibration_v2.json`），v2 test 新跑一次；B0-original 0.35 历史保留。
  - `semantic`：bge-small 向量；dev 用同一 101 点 grid、FPR≤1/8、Recall@5 优先校准；锁定 **0.65** 后 test 只跑一次。
  - `hybrid`：semantic 分数做可用性门，字符 bigram BM25（k1=1.5、b=0.75）+ RRF（k=60）只重排通过门的候选；使用同一语义阈值，未在 test 调参。
- **最终证据**：所有组仍走现有 N06 版本复核 + N07 `_finalize_rag`；没有 Fake rank/distance，没有 LLM rerank。
- **预计算向量**：`bge-small` 运行 peak RSS **735.2MB**；chunk encode 357.2ms、46 条 query encode 856.7ms；query embedding p50/p95 **23.304 / 30.474ms**。这是离线预计算延迟，不是在线服务延迟。

## Dev 校准

| Group | Threshold | Dev Recall@5 | Dev no-answer FPR | Dev citation precision |
| --- | ---: | ---: | ---: | ---: |
| B0（锁定） | 0.20 | 2/8 | 1/8 | 2/3 |
| semantic | 0.65 | 1/8 | 1/8 | 1/2 |
| hybrid | 0.65 | 1/8 | 1/8 | 1/2 |

- 语义 dev 在 0.30–0.50 区间可到 Recall@5 8/8，但同时 FPR 7–8/8；按预先声明的 FPR≤1/8 约束，只有 0.64–0.65 可行，于是选中 0.65。
- 这是一个**可行性边界**结果：小语料 + 8 个负例不足以让语义分数同时获得高 Recall 和低误报。
- 测试阈值在 test 前锁定；test 没有用于调阈值。

## 结论

1. **语义/hybrid 没有在 Recall 上赢 B0-calibrated。** 语义 7/21 vs B0 9/21；但语义的 no-answer FPR 从 8/9 降到 3/9，引用精度从 52.94% 升到 70%。这是一个**精度/拒答与召回之间的权衡**，不是全面胜出。
2. **语义候选排序本身很强，瓶颈在阈值。** semantic/hybrid 的 diagnostic candidate Recall@5 = 21/21，说明 Gold 总在前 5 个候选里；但 dev 校准出的 0.65 阈值把大量正确候选过滤成 `low_confidence`，最终 Recall 只有 7/21。
3. **B0-calibrated 的 0.20 阈值在 test 上明显过拟合。** dev FPR 1/8，test FPR 8/9；Recall 从历史 0.35 的 6/21 升到 9/21，但误报大幅恶化。阈值只在 dev 校准的规则被遵守，结果如实保留。
4. **hybrid 在本实现下与 semantic 最终指标相同。** BM25 只在已通过语义阈值的候选内重排；Gold 低于阈值时 BM25 无法把它救回。RRF 没有改变最终 top-5 的召回/误报。不能把“混合”写成已证明更好。
5. **没有切换生产默认路径。** 用户已确认本轮只做评测与建议；语义/hybrid 的相对优势不足以支持直接替换 B0，且生产化还需要真实 embedding 后端、collection 重建和 `/chat` 复验。
6. **B0 历史未被覆盖。** B0-original 0.35 结果、校准文件、冻结数据全部只读保留；H2-5 新结果在 `evaluation/reports/H2-5/`。

## 新发现的问题与限制

- **环境偏离协议**：conda Python 3.11.14 + CUDA torch 用于 CPU 推理，不是 Python 3.12/CPU 独立环境；本报告记录版本、设备、线程、peak RSS，不宣称完全复现实验协议。
- **模型选择**：bge-small 是 RAM 约束下的选择，不声称优于 bge-m3；没有做多模型挑优。
- **阈值泛化**：dev 8 个负例，test FPR 与 dev 差异大；不能把小样本校准当成统计保证。
- **hybrid 设计**：语义阈值先过滤再 BM25/RRF，BM25 无法召回低于阈值的 Gold；如果改成真正的融合分数，需要重新预声明并重新校准，不能在看过 test 后改。
- **延迟**：query embedding 是离线预计算；retrieval p50/p95 不含模型；不能把两者相加包装成在线服务 SLA。B0 历史与新跑的 Chroma 条件不同，不直接比较绝对延迟。
- **成本**：本地 CPU，无外部 API；费用记 N/A/0，不代表没有计算成本。
- **生产切换**：未做；需要另一任务增加生产 embedding 后端、依赖/服务、collection 重建、回退开关和真实 `/chat` 复验。
- **过程异常**：第一次 dev 尝试在 publication 向量加入前失败；第二次在候选字典里加了 `frozen_chunk_id`，`RetrievalHit(extra='forbid')` 导致所有 `_finalize_rag` 变成 degraded；修正后才产生锁定校准。无效 dev run 保留在 `evaluation/reports/H2-5/dev/` 并由 `README.md` 标明；top-level `calibration.json` 只指向有效 run。
