## 调用路径变化

`SingleSupportAgent.handle` 在原有交接守卫内新增：

1. 计算 `evaluate_action_claims(response.content, response.tool_traces)`；
2. 回答声称已创建交接但 `req.handoff.handoff_created=False` → `handoff_created_without_receipt`；
3. 改写优先级：
   - 有 `request_handoff` trace → 动作回执 + `handoff_reply`（原行为）；
   - 否则有 blocking 动作声明 → `_last_action_receipt()`，没有回执则固定话术“本次没有已完成的状态变更动作；相关退款/取消尚未执行。”；
   - 否则交接完成声明 → `handoff_reply`（原行为）。
4. `consistency_warnings` 写入 `AgentResponse` → `SupportResult` → Trace 根节点，`/trace/tool/{request_id}` 可查。
5. `output_consistency=False`（仅评测消融）不检查、不改写，warnings 为空。

## 检查项

| warning code | 触发 | 处理 |
| --- | --- | --- |
| `refund_completed_without_execution` | 回答称退款完成，但本轮 `request_refund` 没有 `completed` | 改写为动作回执或固定如实话术 |
| `cancel_completed_without_execution` | 回答称订单取消完成，但 `request_cancel_order` 没有 `completed` | 同上 |
| `refund_arrival_unverifiable` | 回答称“已到账/已退回” | 改写为回执；模拟后端不能证明真实到账 |
| `handoff_created_without_receipt` | 回答称已创建交接，但 `handoff_created=False` | `handoff_reply`（“本次未创建人工交接记录。”） |

## 新发现的问题与限制

- 措辞检查是窄启发式，不是完整事实核验；“钱已到您卡里”等变体仍可能漏检。
- 改写会替换整段回复（沿用交接守卫风格），可能丢掉有用信息；只在 blocking 命中时发生。
- “到账”在模拟后端永不可证明，因此即使动作 `completed` 也会改写为回执。
- 只覆盖退款/取消/交接/到账四类；其他状态声明（如“已发货”）仍以 Provider 结果与提示词约束为主。
- 没做真实模型回归；模型是否因此更少产生不一致回答，需要 H3-6 对比（同预算）。
