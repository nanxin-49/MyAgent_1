## 真实模型冒烟（准备阶段）

用户确认当前无预算上限；本轮共 5 次真实 `/chat`：3 次 API 冒烟 + 2 次浏览器截图场景，不用于录屏或质量指标。

### 首次失败与根因

- 首次 UI 请求 401：token 与 user_id 不匹配或 token 为空；换成对应凭据后继续。
- 随后 `/chat` 返回 200，但日志为 `model not found: deepseek-flash`，请求发到 `127.0.0.1:15721`。
- 根因：Claude Code 终端注入的 `ANTHROPIC_BASE_URL` / `ANTHROPIC_API_KEY` / `ANTHROPIC_MODEL` 覆盖了 `.env`；`load_dotenv` 不 override 已有环境变量。
- 修复启动方式：`env -u ANTHROPIC_BASE_URL -u ANTHROPIC_API_KEY -u ANTHROPIC_MODEL uv run python -m uvicorn ...`，让 `.env` 配置生效。已写入 `docs/demo-script.md` 的启动说明。

### 冒烟结果

| 场景 | 结果 |
| --- | --- |
| 政策问答（首次） | HTTP 200；`search_knowledge_base`；`retrieval_status=usable`；但回答被输出一致性误判替换为“本次没有已完成的状态变更动作” |
| 复合售后 | HTTP 200；`get_order`/`get_refund_status`/`request_refund`；两个 action：`completed` + `awaiting_approval`；约 7.2s |
| 政策问答（修复后） | HTTP 200；完整政策回答；`retrieval_status=usable`；citation + `refund-cancel-v1`；`consistency_warnings=[]`；约 7.1s |

结论：真实模型、真实 Redis/Chroma、模拟 backend 的核心链路可用；没有把冒烟当 Demo 质量或生产指标。

### 政策问答误判修复

- 现象：政策回答包含知识原文的“已完成退款记录”“退款到账后”等描述，被 `core/output_consistency.py` 当成“本轮退款已完成”的声明，blocking warning 把整段回答替换成固定回执。
- 根因：完成声明正则只检查匹配前缀的否定词，没有排除“记录/的/时/后/条件/政策/规则/流程/状态”等描述性后缀。
- 修复：增加 `_NON_CLAIM_SUFFIX`；新增 3 条政策措辞回归测试；真实政策问答重新返回完整政策、citation，`consistency_warnings=[]`。
- 最新证据：`tests/test_h3_4_output_consistency.py` **26 passed**；`docs/reports/H3-4.md` 已记录后续修复。

## Docker 环境问题记录

这些是本机环境问题，不是 CartCare 代码缺陷；已写入 `docs/operations.md` 的 Docker 常见问题。

1. **app 镜像构建失败**：`docker compose up -d --build` 在拉取 `python:3.12-slim` 元数据时 Docker Hub 连接超时（`auth.docker.io`）。本地无该基础镜像缓存，因此 `cartcare-app` 未构建；Dockerfile/依赖未验证。当前用本地 uvicorn。
2. **Windows 端口排除**：`netsh interface ipv4 show excludedportrange protocol=tcp` 显示 `6291–6490` 等范围被系统保留，6379 和 6380 都 bind forbidden。改用 `REDIS_PORT=16379`，Compose 已支持该变量；本地 `REDIS_URL` 使用 16379。
3. **旧网络子网重叠**：旧 `echomind_echomind-network` 占用 `172.28.0.0/16`，导致新 `echomind_cartcare-network` 创建失败；删除旧网络（无容器后）后恢复。
4. **旧 app 容器不在 Compose 管理内**：`echomind-app` 单独占用 8000；已停止并删除。旧 Redis/Chroma 数据卷 `echomind_redis-data` / `echomind_chromadb-data` 保留，未执行 `down -v`。
5. **容器曾同时退出一次**：Redis/Chroma 在这次准备中同时 Exited(0)，原因未确认（Docker Desktop/资源状态）；重新 `docker compose up -d redis chromadb` 后恢复。当前 `cartcare-redis`（16379）与 `cartcare-chromadb`（8001）healthy。
6. **Compose 项目名仍为 `echomind`**：目录名决定 project name，卷/网络前缀仍是 `echomind_*`；容器名已是 `cartcare-*`。这是为保留数据卷，未强制改 project name。
