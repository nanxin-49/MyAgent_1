# CartCare 重点代码

## 可执行生产请求路径

api/main.py 的 lifespan 创建 agents/support_agent.py 的 SupportRuntime，注入原有 RAG 和业务工具。/chat 读取 Memory、构建 Request、调用 runtime.run、回写 Memory，再返回响应和引用；不调用 recognize_intent、specialist routing 或 Composer。

SupportRuntime 每请求创建独立 SingleSupportAgent，复用 agents/agent_orchestrator.py 的 BaseAgent 和 Request / AgentProfile 类型。统一注册表合并原有 helper tools 与共享工具。提示词、角色契约、skills 文本、generation 0.2 / 1200 与已验收 T10 Single 一致，只有 Agent identity 改为 support。不会以 case 标签引导生产行为。请求独立 Agent 状态避免并发污染 _last_tools。

```text
Memory / context → SupportRuntime.run → SingleSupportAgent.handle
→ BaseAgent._call_llm（最多 3 轮 Tool Calling）
→ agents/tools.py → core/tool_contract.py → guarded handlers
→ Response / Trace / Memory 回写
```

## 统一工具和确定性业务层

agents/tools.py 的 build_business_tools 提供 get_product、get_order、get_shipment、check_inventory、get_refund_status；Provider 从 Request.user_id 获取身份并检查 ownership，不接受模型覆盖客户身份。

build_action_tools 的 request_refund / request_cancel_order 仅请求 ActionService。actions/ 保留 PendingAction、状态机、审批/拒绝/恢复、执行器和幂等 Store；policies/ 保留基于 Provider 事实的确定性资格、金额和风险规则。/actions/{id}/approve、reject、resume 的 API 未改。危险工具不通过 Tool Runtime 自动重试或绕过审批。

core/tool_contract.py 提供严格 schema、风险/超时/重试元数据、typed result、错误和审计 trace。所有工具对 Single 可见不等于获得直接写后端能力。

## RAG 与 Memory

build_shared_rag_tools 提供 search_knowledge_base；mcp/tool_manager.py 保留改写、HTTP 检索、去重、重排、缓存、熔断和 fallback。mcp/rag_contract.py 定义文档与 citation/source contract；mcp/knowledge_base.py 使用外部 HttpClient 与版本化 collection，embedding 实现和 0.35 阈值未改。

api/main.py 的 collect_rag_evidence / render_rag_citations 继续向响应暴露可靠来源。citations 是检索证据，不代表逐句事实核验。MemoryManager 的 Redis、情景摘要、profile 更新路径未修改。

## Trace / API / Monitor 兼容性

/chat 和 /trace/tool/{request_id} 标记 topology=single、agent_type=support；agent_types=[support]。primary_agent、supporting_agents、routing_reason、routing_confidence 保留为 nullable deprecated API 字段并返回 null；intent、intent_group、intent_confidence、intent_source_scores 为空。没有伪造 general 路由。仓库内未发现前端依赖这些字段，外部消费者需适配 nullable 值。

core/model_observation.py 用 ContextVar 记录 Support 和 RAG SDK create 次数、usage、延迟和错误类型，不保存 prompt 或隐藏推理；不统计 Memory/profile、SDK 内部 HTTP 重试。SupportRuntime 保留有界 trace 和请求统计。PerformanceMonitor 检查 supports_routing=False，继续观测性能而跳过路由评分/建议。

## Eval 与历史 Multi

/eval/run 使用当前 SupportRuntime 生成回复，LLM judge 只处理主观回复质量；默认不运行 intent cases，显式请求才诊断 IntentRecognizer。确定性 Tool/Policy/RAG/HITL 正确性仍通过专项 Eval 评分。

agents/agent_orchestrator.py 中旧 General / Technical / Billing / Escalation、Intent 路由、supporting 路径和 Composer 未物理删除，仅供历史测试和 evaluation/run_topology_comparison.py 实验使用。生产入口依赖该模块的 BaseAgent / 数据类型，不实例化 AgentOrchestrator。evaluation/topology_experiment.py 的实验 Single 保留原样。

T09/T10 dataset 和历史 report 未改。T10 最终 60 样本详见 evaluation/reports/t10_topology_comparison.md；supporting/composition 使用均为 0。失败 specialist 的 fallback 前调用由 T10 runner 完整记录，旧 Multi 最终 Trace 可能遗漏此证据的历史问题不在本次顺手修复。

## 迁移验证入口

- tests/test_support_production.py：十场景 HTTP 接线、prompt/registry 与实验一致、引用、安全 schema、审批不能绕过、批准重复执行幂等。
- 现有 tests/test_action_service.py / test_policy_engine.py / test_business_tools.py：业务规则、安全、reject/resume/idempotency 回归。
- evaluation/run_system_eval.py：确定性 component replay，不是在线模型质量。
- evaluation/run_support_regression.py：独立 localhost HTTP server，实际 /chat、真实模型/Chroma HTTP、演示 fixture，固定空 Memory adapter 与逐 case 新鲜 RAG cache。Redis/长期 Memory 未测，报告独立保存且拒绝覆盖已有 observations。

生产回归 report：evaluation/reports/support_production/regression.md / regression.json；原始 response/trace：observations.json。task success 8/10、危险动作 4/5、安全违规 0；失败为 unsupported 升级标记和 ownership 严格证据缺口。不必要调用 3/10，单轮结果不证明稳定变化。生产迁移建议 verify；保留 legacy 实验，不恢复生产 intent dispatch。

## 真实 Memory 集成验收

evaluation/run_support_memory_acceptance.py 在独立本地 HTTP 服务上使用原有 MemoryManager、项目 Redis/Chroma 和真实模型。首轮 `get_order` 后，Redis 保存用户与助手消息；第二轮无订单号请求从会话取回同一订单号，`get_shipment` 得到匹配物流。另一用户不会读取该订单；OpenAPI 和实际 Trace 的旧 routing 字段均是 nullable/null。故障注入仅将该运行实例的 Redis client 指向关闭端口，原服务不停机：请求返回 HTTP 500，Agent 未执行，恢复后原会话可读。结果见 evaluation/reports/support_production/memory_acceptance.md。长期记忆压缩与 profile 质量仍未专项测试。此前固定空 Memory 的十场景报告仍按其原条件解读。

evaluation/run_baseline.py 的兼容读取也已校正：Single 响应的旧路由字段为 null，旧 Intent / routing 指标返回未观测，不从 support 身份推断 primary Agent；历史 Multi 评测语义保留。
